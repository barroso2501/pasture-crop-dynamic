# Decision 024 — technical closure, interpretation and assurance scope v2

**Date:** 2026-10-09. **Status:** technical closure recorded; scientific interpretation qualified; remaining assurance and release tasks explicit.

The 2026-10-08 [v1 closure](024_implementation_closure_v1.md) and its validation JSON remain historical records. They accepted the 12 criteria through the documented execution/source/panel evidence chain. This supplement does not certify an additional native Earth Engine run or rewrite historical PASS flags. The current interpretation is [erratum v4.1](../results/decision024_origin_window_erratum_v4_1.md), with unchanged numerical source summaries.

## What is completed

Eight corrected PAS origin-by-destination cell tables, corrected panel-chain comparisons, 2024/2025 boundary-event audit, source-anomaly audit, fixed-cohort revalidation and a versioned corrected evidence record are available. The supplementary PAS→NAT interval and pooled summaries and direction comparison are now produced from the authenticated cell CSVs, completing that reporting item in plan 008 v3. RQ2 remains PAS→TMP.

## What the closure does not establish

The synthetic verification executes extracted production source logic through a local scalar adapter, plus the original pilot's local preflight functions. It does not execute the GEE image/reducer graph in the native service. Criteria 3 and 5 are supported by deterministic source logic and the accepted processing chain, not a new exported all-pixel invariant audit. Aggregate closure does not independently prove each pixel's attribution. Criterion 9 preserves non-origin values in the versioned chain and compares PAS totals; it does not independently re-export NAT→TMP or TMP→* raster flows. Phases 2–8 were not rerun in the remediation.

Accordingly, use 'technical closure within the documented evidence scope'; do not state that the closure proves exhaustive native-pixel verification of every criterion. The earlier unconditional wording was too broad. A direct native GEE invariant export would strengthen assurance of criteria 1/3/5 and is a targeted pending assurance task, not a completed result. Historical null executed-script hashes remain provenance gaps; current script hashes cannot fill them retrospectively.

## Remaining tasks and boundaries

Window-start sensitivity is pending. Observed first-entry versus observed re-entry decomposition is proposed and pending. All-pixel native assurance and PAS-conditioned uncertain-pair cross-tabs are pending if stronger validation or population claims are sought. DOI release packaging and portable data access remain pending. These tasks do not invalidate the qualified arithmetic descriptions or require indiscriminate rerunning of phases 2–8. They must not be described as already done.

The public dataset release must include the eight cell CSVs and the corrected v2 panel and derivative dependencies, with versioned DOI access and field dictionaries. The data are not all included in this compact GitHub ZIP. No DOI has been minted by this review.
